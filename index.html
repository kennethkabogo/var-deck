The Problem
Agents act.
Nobody can prove what they did.
When an AI agent executes a financial transaction, routes a payment, or makes a compliance-critical decision — the only record is a software log. Software logs can be altered. Any compromised host can silently rewrite them. There is no cryptographic proof of what the agent decided, what data it saw, or whether the binary running it was tampered with. This isn't a crypto-specific failure mode — it's what happens anywhere an autonomous agent's actions are trusted without hardware-rooted proof underneath them: capital markets, freight and logistics, insurance claims, compliance-critical workflows generally.
Case in point — April 18, 2026

KelpDAO lost $290M because their verifier had no hardware-level execution boundary. Lazarus Group swapped binaries on the RPC nodes feeding the verifier. The malicious nodes showed truth to monitors, lies to the verifier. No attestation. No recourse. In a VAR architecture this attack fails at step one — a binary swap changes the PCR0 measurement, the KMS policy gate closes, and nothing settles. It's the clearest public example because the failure is already visible and priced in DeFi — but the underlying gap is the same wherever an agent acts without hardware-rooted proof.

The Solution
VAR — Verifiable Agent Runtime
VAR wraps any AI agent in a hardware-attested enclave. Every action produces a cryptographic receipt in real time — hardware-signed, PCR-bound, independently verifiable by any third party without trusting the operator or the host. The proof is produced during execution, not reconstructed afterward. By the time the agent finishes, the evidence already exists.

Confidentiality ≠ Accountability.

What we understand that they don't

The accountability problem and the confidentiality problem are distinct. Most confidential computing is built for an operator protecting their own data from a cloud provider. VAR is built for the counterparty — the regulator, auditor, or enterprise buyer — who needs proof the operator didn't tamper with evidence. That operator-untrusted constraint requires hardware enforcement: PCR-gated KMS Decrypt makes it impossible for the operator to access the signing key without running the exact audited binary. No competitor has designed for an adversarial operator. The APEX spec is open-source — the moat is the operational expertise to run this at institutional grade, built from years spent finding the holes in these systems from the attack side.
